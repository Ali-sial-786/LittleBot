# Audio module (`littlebot/audio/`)

Speaker + microphone devices, child-friendly sound effects, a music-box melody synth,
text-to-speech (TTS), speech-to-text (STT) and the half-duplex `AudioService`
that implements `core.interfaces.AudioAPI`.

```
littlebot/audio/
  __init__.py      create_service(ctx) -> AudioService (lazy imports)
  service.py       AudioService: output queue/thread, speech events, listen(), privacy, volume, diagnostics
  devices.py       output/input backends, device enumeration + selection, auto fallback
  sfx.py           procedural sound effects, note parser + melody synth, SoundBank (WAV loader)
  vad.py           energy voice-activity detection
  dsp.py           numpy helpers: WAV encode/decode (in memory), resampling, level envelope
  errors.py        AudioDeviceError, TTSError, STTError, CloudNotAllowed
  tts/             base, mock, espeak (espeak-ng), piper, openai (cloud, gated)
  stt/             base, mock, vosk (optional), openai (cloud, gated)
assets/sounds/*.wav       generated by scripts/generate_sounds.py (commit them)
scripts/check_audio.py    device diagnostics for the Pi / desktop
```

## Public behaviour (AudioAPI)

| Method | Behaviour |
|---|---|
| `say(text, rate=None)` | Cleans text (no emoji/control chars, max 300 chars), synthesises **off the loop** (`asyncio.to_thread`), queues it, waits. Publishes `audio.speech_started {text, duration_estimate}` -> `audio.level {level}` at ~16 Hz from the audio envelope -> `audio.speech_finished {text, interrupted}`. Returns `False` if interrupted, the speaker is disabled/unavailable, or synthesis failed everywhere. `rate` replaces the `audio.tts_rate` setting for that call (clamped 0.5..1.6). |
| `play_sound(name, wait, volume)` | A name from `SOUND_NAMES` or a relative `.wav` path under `assets/sounds/` (no `../` escapes). `volume` is **relative** (0..1 x master volume) so it can never be louder than the parent's setting. Publishes `audio.sound_started/finished {name, interrupted}`. |
| `play_melody(notes, tempo_bpm, wait)` | `[("C4", 1), ("F#4", .5), ("R", 1), ("Bb3", 2)]`. Invalid input -> logged, returns `False` (never raises). Same sound events with `name: "melody"`. |
| `stop_output()` | Drops the queue and interrupts the current item within one chunk (~50 ms); also cancels speech that is still being synthesised. Speech publishes `speech_finished {interrupted: true}`. |
| `listen(timeout)` | Half-duplex (below). `timeout` = seconds to wait for speech to **start** (default `microphone.max_record_seconds`). Publishes `audio.listening_started/stopped`, then `audio.utterance {text, confidence, source: "stt"|"simulated"}`. `None` if nothing heard, mic disabled/unavailable, cancelled (`STOP_ALL`, privacy) or a second concurrent `listen()`. |
| `inject_utterance(text)` | Simulated mic input: satisfies the pending or next `listen()` (expires after 120 s, max 5 queued). Dropped while the microphone is disabled. |
| `set_volume(v)` | Clamped to `[0, audio.speaker.max_volume]` (safety ceiling), applied immediately (gain is re-read every chunk), persisted as `audio.volume`. Raises `ValueError` for non-numbers/NaN. |
| `list_devices()` | `{inputs, outputs: [{index, name, default, channels, default_samplerate, hostapi}], portaudio, detail, selected}` |
| `test_speaker()` | Plays `chime`; `{ok, backend, device, status, volume, detail}`. On a simulated/missing speaker `ok=False` with a hint. Rescans devices first if none was found. Never raises. |
| `test_microphone(seconds)` | Records in memory only, keeps just peak/RMS: `{ok, backend, device, peak, rms, seconds, detail}`. Never raises. |
| `status()` | `{speaker: {backend, device, status, detail}, microphone: {...}, volume, max_volume, speaking, playing, queued, listening, mic_muted, half_duplex, tts_provider, stt_provider, tts_rate, last_error}` |

Device `status` values: `ok`, `simulated` (mock), `disconnected` (failed mid-use, retried every 5 s),
`unavailable` (not found), `disabled` (config `none` or privacy). Every change is published as
`audio.device_status {device: "speaker"|"microphone", status, detail, backend, name}`.

Lifecycle state lives in `service_status` / `health()` (core `Service` base class).

## Output path

* One daemon thread (`littlebot-audio-out`) plays a bounded queue (16 items) in order.
* Backends take mono float32 and play in ~46 ms chunks; the digital gain
  (`volume x item volume`, capped at `max_volume`) is ramped per chunk (no zipper clicks).
* **Speaker missing or unplugged**: the item is "played" on a simulated speaker so the face still
  gets speech/level events and activities keep their pacing, but the call returns `False`.
  A `disconnected` real speaker is re-opened at most every 5 s (PortAudio is re-initialised
  only when no stream is open, so a re-plugged USB speaker re-appears).
* The PortAudio stream stays open while sounds follow each other and is closed after 3 s of
  silence; a 30 ms silent lead-in on (re)start stops USB speakers swallowing the first syllable.

### Backends and `auto`

| config | speaker | microphone |
|---|---|---|
| `auto` | `sounddevice` (PortAudio) -> `pygame` SDL mixer (not the dummy driver) -> `mock` (warning, `simulated`) | `sounddevice` -> `mock` (inject_utterance still works) |
| explicit (`sounddevice`/`pygame`/`real`) | that backend; if missing it stays `unavailable` (retried), never silently mocked | `real`: same |
| `mock` | `MockOutput` (real-time timing in the app, instant in tests via `ctx.clock.scale`) | `MockInput` (noise floor + injected audio) |
| `none` | `NullOutput` (`say` returns `False` immediately) | `NullInput` (only simulated input) |

Device selection: `device: null` = system default; an integer = PortAudio index; text =
case-insensitive substring of the device name (e.g. `"USB"`). Sample rate falls back from the
configured rate to the device default / 48000 / 44100 and audio is resampled (FFT for whole
buffers, phase-continuous linear + anti-alias for the mic stream). Stereo-only USB devices get
duplicated mono.

## Half-duplex design (echo prevention)

LittleBot never listens to itself:

1. The microphone stream is **only open while `listen()` / `test_microphone()` run**
   (privacy + CPU). It is closed again before `listen()` returns.
2. `listen()` first waits for queued/playing output to finish (bounded, 30 s), then for
   `audio.post_speech_mute_seconds` (0.4 s; via `ctx.clock.sleep`, instant in tests).
3. While anything is queued or playing, or within the post-speech window, captured chunks are
   discarded and the VAD is reset (e.g. an activity plays a sound while a listen is running).
4. VAD (`vad.py`): speech starts after 60 ms above `microphone.vad_threshold` (RMS, with an
   adaptive noise floor x3), ends after `silence_seconds` below 70 % of it, capped at
   `max_record_seconds`; bursts under 0.2 s (claps, bangs) are ignored; 0.3 s pre-roll.
5. The utterance goes to STT in memory and is dropped afterwards. Nothing is written to disk
   unless `audio.store_recordings: true` (then `data/recordings/utterance-*.wav`).

## Privacy

* `privacy.microphone_enabled = false`: `listen()` returns `None` immediately (no events), an
  in-progress listen is cancelled and the stream closed (`privacy.changed` handler),
  `inject_utterance` is ignored, `status().microphone.status == "disabled"`.
* Cloud TTS/STT (OpenAI) use the **same gates as the cloud AI conversation**, re-checked by the
  service before every call (also for injected providers): `ctx.privacy.cloud_enabled` (never in
  offline mode), an `OPENAI_API_KEY`, the child's age **if** `ai.min_age_months_for_cloud` sets a
  minimum (`ctx.age_policy().cloud_ai_allowed()`; default 0: any age, so with cloud AI on an infant's
  voice can be uploaded, e.g. during activity listens) **and** the parent's `ai.enabled` opt-in.
  Otherwise, and on any failure (401, 429, timeout, bad audio), the local provider is used for
  that call. `provider: auto` never picks a cloud provider. Keys are never logged.
* Cloud TTS text: unless the parent turned on `ai.share_child_name`, the child's nickname
  (`profile.nickname`, case-insensitive, whole words; a multi-part name also part by part) is
  replaced by "friend" before the text is sent (`tts.base.scrub_names`). Local voices and the
  `audio.speech_started` event keep the original text.
* `status().tts_provider` / `stt_provider` say why a configured cloud provider isn't used
  (`"mock (openai needs cloud + key)"`, or with a minimum age set
  `"mock (openai not allowed: child under 24 months)"`).
* No transcripts are logged. Speech text appears only in bus events (as before).

## Speech providers

| provider | notes |
|---|---|
| `mock` | no voice; very quiet soft "babble" blips with realistic duration (words / 2.5 s / rate) so the mouth moves (`style="silence"` also available) |
| `espeak` | `espeak-ng --stdout --stdin -v en-us+f3 -p 65 -s 160*rate -g 2` (text via stdin: no option injection), gently low-passed and normalised. `auto` uses it when installed |
| `piper` | `piper --model <audio.tts.piper_model> --output_raw` (binary must be on `PATH`); one process per phrase (~0.5-1.5 s model load on a Pi 5, UNVERIFIED) |
| `openai` | `POST /v1/audio/speech` (`gpt-4o-mini-tts`, voice `shimmer`, WAV, soft-voice instructions), 15 s timeout, cloud + age + `ai.enabled` gated, nickname removed without `ai.share_child_name`, falls back to local |

STT: `mock` (returns queued text), `vosk` (`pip install vosk` + `audio.stt.vosk_model_path`, small
English model ~40 MB, loaded lazily), `openai` (`/v1/audio/transcriptions`, multipart WAV built in
memory, cloud + optional minimum age + `ai.enabled` gated). `auto` = vosk if configured, else mock. With mock STT a real microphone
still detects speech, but `listen()` returns `None` (no transcription) - configure vosk/openai.

## Sound effects

`scripts/generate_sounds.py` synthesises all `SOUND_NAMES` deterministically into
`assets/sounds/<name>.wav` (mono, 16-bit, 22050 Hz, ~730 KiB total). Rules: sine / music-box /
bell / soft-noise timbres, >= 6 ms raised-cosine attacks, exponential tails, peak about -6 dBFS,
RMS <= -16 dBFS, < 2 % energy above 6 kHz (all enforced by tests). `--check` verifies the
committed files. `SoundBank` loads WAVs lazily (cached) and synthesises a missing built-in.

Melodies: note names `C4`, `F#4`, `Bb3`, `G♯4`, `D♭5`, `C` (octave 4); rests `R`/`rest`/`-`/`_`;
beats in (0, 16]; tempo 20..300 bpm; pitches limited to ~60-2200 Hz; max 60 s. Each note is a
soft music-box/xylophone tone (fundamental + fast-decaying overtones, 8 ms attack, 120 ms decay to
sustain, 220 ms release).

## Raspberry Pi 5 device setup

The **Pi 5 has no 3.5 mm audio jack**: use a USB speaker (or HDMI audio) and a USB microphone
(or a USB webcam's mic).

1. `aplay -l` / `arecord -l` should list the USB card(s) (e.g. `card 2: Device [USB Audio Device]`).
2. `.venv/bin/python scripts/check_audio.py --list` shows what PortAudio sees and which device the
   config selects. Then `--play` (chime + sentence) and `--record 5` (live level meter, not saved).
3. **Pi OS Bookworm uses PipeWire.** PortAudio reaches it through its ALSA `pipewire` / `pulse` /
   `default` devices. Easiest: make the USB speaker the default sink (`wpctl status`,
   `wpctl set-default <id>`) and keep `device: null`. With plain ALSA (or to bypass PipeWire), set
   a name substring in `config/local.yaml`:
   ```yaml
   audio:
     speaker:    {backend: sounddevice, device: "USB Audio"}
     microphone: {backend: real, device: "USB PnP"}
   ```
   Direct `hw:` devices only support their native rates (44.1/48 kHz): LittleBot resamples.
   A device opened directly via `hw:` is exclusive ("device busy" if another program holds it).
   The face only initialises pygame's display/font modules, so the SDL mixer is opened only by the
   audio `pygame` fallback - keep it that way (a bare `pygame.init()` would also open the mixer).
4. Quiet / silent mic: `alsamixer -c <card>` (F4 capture level) or `audio.input_gain` (dashboard).
5. Speaker too loud/quiet: the dashboard volume is capped by `audio.speaker.max_volume` (0.8);
   also check the USB speaker's own hardware volume / `alsamixer` playback level once.

## Verified vs unverified

* **Verified here (container without sound devices, 177 tests):** all logic with mock devices;
  real `SoundDeviceOutput/Input` code paths against a fake PortAudio module (device selection by
  name/index/default, sample-rate + stereo fallback, gain, PortAudio error mid-stream -> reconnect,
  input stall -> disconnected, stream reuse/release, re-init guard); SDL mixer backend with the
  dummy driver; `auto` degradation with no devices; espeak-ng synthesis; piper via a fake binary;
  OpenAI TTS/STT request shapes, 401/429/5xx/timeouts/garbage responses via `httpx.MockTransport`;
  cloud gating (privacy, a configured minimum age / unknown age, `ai.enabled` off: no request at all; nickname
  never in a cloud TTS request body without `ai.share_child_name`); privacy; half-duplex; no disk writes; `check_audio.py --list` runs and exits 0.
* **Mock-only:** everything audible. No sound was actually heard or recorded.
* **Needs real hardware (UNVERIFIED):** real PortAudio/ALSA/PipeWire behaviour on the Pi 5 (USB
  hot-plug, latency values, level-event sync with the mouth, `pygame` fallback on a real card),
  microphone VAD threshold for a real room and toddler voices, Vosk accuracy/memory on 2 GB,
  piper latency, OpenAI endpoints with a real key, CPU use of the output thread on the Pi.
